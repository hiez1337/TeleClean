# Надёжность и производительность · 3.0.2

Проверена C#/WinUI-версия относительно `winui` на `fa85ff1`: загрузка диалогов, восстановление сессии, фоновая загрузка аватарок, массовая обработка, настройки и локальное хранение. Работа выполнялась в `F:\TeleClean`, ветка `audit/core-reliability` от `origin/winui`. Реальные диалоги, подписки и сессия пользователя для тестов не использовались. Управление компьютером не применялось.

## Подтверждённые дефекты и исправления

P1 — потеря данных, неверный результат операции или смешение аккаунтов; P2 — задержки, отзывчивость и качество проверок.

| Приоритет | Место и условие до исправления | Последствие | Изменение |
| --- | --- | --- | --- |
| P1 | `CacheService.AppendHistoryAsync` читает весь JSON, переносит только записи с `dialog_id` и переписывает файл | При первом действии исчезают старые Python-записи со сводкой и ошибками. Суммарный объём чтения и записи растёт квадратично с числом записей | Новые записи дописываются построчно в JSONL. Старый JSON не изменяется; чтение объединяет оба формата. Повреждённая строка не скрывает соседние записи |
| P1 | `CacheService.SaveAvatarAsync` открывает существующий файл через `FileMode.Create` до получения всего потока | Ошибка загрузки или неверный заголовок уничтожает предыдущую аватарку | Запись во временный файл, проверка заголовка, затем замена. Кэш диалогов использует такой же порядок записи и замены; общий `AtomicFile` также используется конфигурацией |
| P1 | `TelegramService.LeaveDialogAsync` игнорирует `messages.affectedHistory.offset` | Длинный диалог отмечается удалённым после первой части | Повтор запроса до `offset == 0`, отмена между частями, передача ошибки наружу без ложного успеха. `revoke:false` сохранён |
| P1 | `DialogListViewModel` не владеет токеном загрузки списка | Запоздалый ответ после сброса аккаунта может снова заполнить список и кэш. Завершение старой загрузки способно изменить состояние новой | Отдельный CTS каждой загрузки, отмена при сбросе/Dispose, проверка токена после ожиданий и проверка владельца в `finally` |
| P1 | В `FetchDialogsAsync` оставался `LoginUserIfNeeded()` с автоматическим повторным входом при ошибке восстановления | Резервный путь загрузки списка использует другой режим восстановления, чем экран входа | Оба пути используют `reloginOnFailedResume:false`; сетевой сбой не переключает этот путь в автоматический повторный вход |
| P2 | `BulkExecutionEngine.Stop` меняет флаг, но не прерывает `Task.Delay(delayBetween)` | При задержке 60 секунд остановка продолжает ждать до конца интервала | Отдельный токен отменяет паузу, интервал и Flood Wait. Он не отменяет отправленный запрос: подтверждённый результат учитывается до остановки |
| P2 | Движок принимает дубликаты и отрицательные интервалы | Повторное действие над одной строкой или ошибка задержки уже после первого запроса | Отрицательные интервалы отклоняются до запуска; уже обработанные строки исключаются; дубликаты удаляются по паре `(тип, ID)` |
| P2 | `DownloadAvatarAsync` выполняет `Array.Find` по всему списку для каждой строки | Для N аватарок — до N² сравнений диалогов | Создаётся типизированный peer, затем используется `UserOrChat`; сканирование массива исключено, пространства пользователей/групп/каналов сохранены |
| P2 | Общий `catch` чтения кэша перехватывает отмену; фоновая задача ViewModel не обрабатывает произвольные ошибки | Отмена выглядит как пустой успешный результат; возможен необработанный fault фоновой задачи | Обработка ожидаемых ошибок хранения отделена от отмены. Фоновая задача аватарок наблюдает исключения и освобождает CTS |
| P2 | Старые тесты фильтрации используют отдельную реализацию алгоритма в helper | Тест может пройти при поломке ViewModel приложения | xUnit компилирует настоящие ViewModel и dispatcher-контракт приложения. Убрано неиспользуемое WinUI-свойство `AvatarImage`, мешавшее независимому тестированию |

Поведение `offset` проверено по [официальному описанию Telegram](https://core.telegram.org/constructor/messages.affectedHistory). На реальных аккаунтах массовые действия не выполнялись.

## Проверки

- 158 офлайн-тестов xUnit: исходные 138 и 20 новых. Новые проверки используют настоящие сервисы хранения, движок, helper пакетного удаления и ViewModel списка. Сеть заменена фейком.
- Проверены поздний ответ после сброса аккаунта, конкурирующие поколения загрузки, Dispose, пустой серверный ответ, недоступная сеть с локальным списком и область выбора после фильтрации/смены категории.
- Проверены совместное чтение старой истории и JSONL, повреждённая строка, несовместимая старая запись, сохранность кэша при отмене, сохранность аватарки при неверном заголовке и обрыве записи.
- Проверены остановка во время минутного интервала/Flood Wait, отрицательные интервалы, типизированные дубликаты и многочастное удаление с ошибкой/отменой.
- Контроль на старых исходниках `fa85ff1`: из шести выбранных регрессионных случаев четыре падают — поздний ответ, уничтожение аватарки, потеря старой истории и ожидание минутной задержки после Stop. После восстановления исправленных исходников эти проверки проходят. Два других случая уже проходили: отмена записи до начала I/O и остановка Flood Wait в пределах двух секунд.
- Штатная сборка WinUI Release x64: 0 ошибок. Имеются прежние предупреждения MVVMTK0045 о генерации свойств для Native AOT; приложение публикуется без Native AOT. Никаких новых обещаний визуальной проверки интерфейса в этом аудите нет.
- Локальная публикация профилем `WinX64` создала один EXE. Файл скопирован в отдельную папку без соседних библиотек: `--demo` и `--demo-login` открывают окно примера и процесс отвечает на сообщения Windows. Это проверка старта, а не визуальная проверка или прохождение сценариев через UI.

Команды воспроизведения:

```powershell
dotnet test src/TeleClean.Tests/TeleClean.Tests.csproj -c Release
dotnet build src/TeleClean.App/TeleClean.App.csproj -c Release -p:Platform=x64
```

## Оставшиеся ограничения

- Отправленный MTProto-запрос не отзывается кнопкой Stop. Завершение текущего действия сохраняется в отчёте. Сетевое зависание может задержать эту часть остановки; мгновенная отмена не заявляется.
- У JSONL пока нет ротации. Добавление записи не перечитывает историю, но полная загрузка журнала по-прежнему требует памяти пропорционально его размеру. Это задача для отдельного экрана истории/пагинации при подтверждённом объёме данных.
- Аватарки проверяются по размеру и сигнатуре JPEG/PNG; полное декодирование не выполняется в Core. Фоновая загрузка последовательная, чтобы не создавать всплеск запросов Telegram.
- Пользовательские API-реквизиты и параметры прокси остаются в локальном JSON, как описано в README. Изменение формата хранения секретов требует отдельной миграции. Текущая задача не изменяет существующие профили пользователя.
- Старые helper-тесты сохранены как дополнительные проверки; они не заменяют новые тесты исходников ViewModel. Native AOT, реальная сеть и повторный вход настоящим аккаунтом этим набором не проверяются.
