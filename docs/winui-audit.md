# Аудит WinUI

Аудит выполнен относительно самостоятельной ветки `winui` на коммите `666bdb6`. Приоритет P1 обозначает риск для данных, авторизации или фактической области операции. P2 относится к обратной связи, хранению и отзывчивости.

| Приоритет | Условие и последствие до исправления | Исправление |
| --- | --- | --- |
| P1 | `DialogListViewModel.LoadDialogsAsync` игнорировал пустой ответ Telegram. При повторном открытии пустой вкладки инициировалась новая загрузка, а устаревшие строки могли остаться доступны для операций. | Пустой ответ заменяет снимок. Ошибка синхронизации оставляет список доступным для чтения и блокирует действия до успешного обновления. |
| P1 | `TelegramService.FetchDialogsAsync` сопоставлял top message по ID сообщения. При совпадении ID у разных собеседников дата могла принадлежать другому диалогу. Аватары и события массовой обработки тоже сопоставлялись по числовому ID без пространства. | Даты привязаны к собеседнику и сообщению. Файлы аватаров разделены по пространству peer, события завершения содержат тип диалога. |
| P1 | `BulkExecutionEngine.Stop` сразу помечал очередь завершённой для проверки повторного запуска. В это время запрос мог ещё выполняться, а UI не получал итоговый отчёт о прерывании. | Очередь удерживает флаг выполнения до завершения и публикует итог с числом обработанных элементов. При Flood Wait учитывается интервал, возвращённый Telegram. |
| P1 | `AuthViewModel` и `MainWindow` оба проверяли сессию. Запоздалые QR-обновления могли попасть в другой режим, а ожидание облачного пароля удерживало клиентский lock после отмены. | Один владелец проверки входа. QR-обновления проверяют токен отмены на UI-потоке. Ожидание пароля прерывается токеном. |
| P1 | `TelegramService.ResetSessionAsync` подавлял ошибку серверного выхода и удалял файлы в нескольких каталогах. Автовосстановление удаляло несовместимый файл. | Ошибка серверного выхода видна пользователю. Сброс работает с выбранным файлом сессии, а несовместимые файлы перемещаются в резервную копию. |
| P1 | Интерфейс называл удаление истории «остановкой бота». Команда начинала работу сразу после нажатия. | Подтверждение называет действие и последствия, показывает число элементов и первые названия. Для ботов указан фактический эффект удаления истории. |
| P2 | `DialogListViewModel` пересоздавал коллекцию построчно и искал аватар линейным обходом списка для каждого ответа. Фоновая работа продолжалась при обновлении и выходе. | Фильтрация публикует один снимок, загрузка аватаров привязана к конкретным строкам и отменяется между запросами. `ListView` виртуализирует строки. |
| P2 | `SettingsViewModel` запускал несинхронизированные записи в один файл. Команда очистки аватаров удаляла и снимок списка. | Записи конфигурации последовательны, файл заменяется после успешной записи. Очистка работает с каталогом аватаров из конфигурации. |

## Проверка и оставшиеся границы

- Офлайн-регрессии покрывают совпадающие peer ID, повторный старт до завершения остановки и ожидание интервала, возвращённого сервером. Скриншоты и ручные проверки выполнены с подменой Telegram и с отдельным временным каталогом.
- В запущенном приложении проверены светлая и тёмная темы, переключение темы через настройки, ширина окна 1100 и 610 пикселей, Ctrl+F, пустой результат поиска, сброс фильтров, обновление после ошибки, ответ с нулём диалогов, область выбора, подтверждение, Escape, пауза и итог остановки. Проверка окон выполнена на одном дисплее с текущим масштабом Windows.
- Действия с реальным MTProto, сессией пользователя и подписками не выполнялись. Точное время остановки текущего запроса зависит от WTelegramClient и сети. Остановка предотвращает следующие запросы.
- Telegram API ID/hash по умолчанию входят в существующую сборку, а сохранённые пользовательские реквизиты и MTProxy хранятся в локальной конфигурации. Миграция пользовательских секретов в защищённое хранилище Windows и разделение унаследованных профилей данных требуют проверки перехода с существующих установок.
- Состояния навигации, фокуса и нажатия основаны на WinUI. Контрольные точки узкого, компактного и широкого окна использованы в соответствии с поведением NavigationView. [Документация Microsoft](https://learn.microsoft.com/windows/apps/develop/ui/controls/navigationview)
